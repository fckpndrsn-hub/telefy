# Выгрузка аудио и подключение Gemini

## Установка

Все файлы из корня Telefy-Export-Gemini.zip загрузите в корень существующего GitHub-репозитория с заменой. Ничего из старого репозитория и web/ не удаляйте. Dockerfile обязателен: он устанавливает FFmpeg и копирует новые Python/JS-модули. Первый деплой может длиться дольше из-за установки кодека.

После Live проверьте /health: `music_features_build: telefy-export-gemini-v1`. Закройте и заново откройте Mini App. BOT_TOKEN, DATABASE_URL, TELEFY_ADMIN_IDS и ключи SoundCloud прежние. Схема PostgreSQL обновляется автоматически. Админка, посты, управление техработами и системные команды плеера сохраняются.

## Выгрузка

1. Пользователь должен хотя бы один раз открыть @TelefyApp_Bot и нажать Start. При отсутствии такого контакта приложение предложит открыть бота.
2. На главной нажать «Офлайн-режим» либо кнопку отправки в бот в большом плеере.
3. Запрос попадает в серверную очередь. Пока файл не отправлен, приложение больше не сообщает ложное «трек выгружен».
4. Один worker готовит MP3 128 kbps: название, исполнитель, ID3-метаданные и встроенная обложка из доступной обложки источника. Боту также передаётся миниатюра обложки. Если обложка у источника отсутствует или не загружается, аудио отправится без неё — чужая картинка не подставляется.
5. Пользователь получает **одно аудиосообщение**, а не документ: файл, название, исполнитель, обложка, подпись и зелёная inline-кнопка «В профиль».
6. Кнопка показывает короткую подсказку в Telegram, без второго сообщения. Само добавление пользователь выполняет через штатный музыкальный плеер Telegram. В Bot API нет метода автоматического добавления музыки в чужой профиль.

Из приложения после подтверждённой отправки можно открыть личный чат бота. Это переход в чат, не автоматический запуск аудио. Для офлайна файл надо загрузить на устройство средствами Telegram. Удаление кэша Telegram может потребовать повторного скачивания. Наличие системной карточки и обложки на экране блокировки после запуска аудио нужно проверить на конкретном Android/iPhone.

Экспорт не превращает текущий поток Mini App в штатный плеер Telegram и не создаёт системную карточку Android для самого WebView.

### Ограничения и надёжность

- Только проверенная Telegram-сессия, подписка на канал и существующий контакт с ботом. Получатель определяется сервером, пользователь не может передать чужой telegram_id.
- Принимается SoundCloud URN, не произвольный URL. Метаданные и адрес потока заново получает backend.
- До 20 минут на трек, одна активная подготовка на очередь, до 30 ожидающих запросов. Для одного пользователя одновременно готовится один трек; между новыми заданиями минимум 30 секунд.
- Временные файлы удаляются после обработки. На Render не создаётся постоянная MP3-библиотека. В PostgreSQL сохраняются задания и Telegram file_id; повторная отправка того же трека использует file_id без новой конвертации.
- Подготовка требует доступа Render к SoundCloud/CDN и использует квоту источника. Более мощный сервер квоту не увеличивает.
- При техработах новые запросы блокируются. Во время подготовки перед отправкой повторно проверяются техработы и подписка. Уже начатую сетевую отправку отозвать нельзя.
- После однозначно неудачной подготовки показывается ошибка. После сетевого сбоя с неизвестным результатом приложение просит проверить чат: автоматический повтор аудио не выполняется, чтобы не дублировать файл.
- Файл кодируется в 128 kbps; настройки потокового качества не означают экспорт в 320 kbps. Перекодирование не улучшает качество источника.

## Gemini с нуля

Google AI Pro для пользовательского приложения Gemini и Gemini API — отдельные подключения. API-ключ не создаётся автоматически от покупки Pro, лимиты и биллинг проекта проверяются отдельно.

**Важное условие перед включением:** [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms) запрещают использовать API в приложении, направленном на аудиторию младше 18 лет или вероятно ею используемом. Ранее Telefy допускает несовершеннолетних; подключение к общему публичному сервису нельзя считать решённым одним API-ключом. Нужно определить подходящую схему/провайдера или получить соответствующее разрешение Google. Этот код не меняет возрастную политику Telefy и не вводит фиктивную проверку возраста. Для пользователей в ЕЭЗ, Швейцарии и Великобритании условия Google также требуют Paid Services; размещение Render во Франкфурте не заменяет условия API.

Техническое подключение, когда условия использования подходят:

1. Откройте [Google AI Studio → API keys](https://aistudio.google.com/apikey). Войдите в Google, выберите/создайте Cloud-проект и создайте ключ для Gemini API. Ключ сюда в чат не присылайте.
2. В Render → telefy → Environment → Edit → Add Environment Variable добавьте:
   - `GEMINI_API_KEY` — ключ из AI Studio;
   - `GEMINI_MODEL` — `gemini-3.8-flash` либо другой совместимый с generateContent JSON-output model ID, доступный вашему проекту;
   - `TELEFY_AI_DAILY_LIMIT` — например `100` (общий максимум внешних запросов в сутки UTC; ошибки тоже учитываются).
3. Save, rebuild and deploy. Дождитесь Live и переоткройте Mini App.
4. В /health появится объект gemini. `configured:true` означает наличие ключа и включённого адаптера, **а не проверенную оплату/валидность ключа**. После успешного внешнего ответа state станет ready. `key_or_project_denied` — проверить ключ, доступ проекта и регион; `model_unavailable` — модель; `rate_limited` — квоты; `daily_limit` — наш дневной лимит.
5. Отключить Gemini: `TELEFY_AI_ENABLED=false` или убрать ключ. `TELEFY_AI_DAILY_LIMIT=0` запрещает новые внешние генерации, сохраняя возможность отдавать уже закэшированные результаты.

Код не включает платный биллинг Google и не привязывает карту. Наличие бесплатной квоты зависит от проекта/модели/региона и условий. Если используется платный API, отдельно задайте доступные ограничения расходов в Google; лимит числа запросов Telefy не является гарантией конкретной суммы в долларах. [API keys](https://ai.google.dev/gemini-api/docs/api-key), [биллинг API](https://ai.google.dev/gemini-api/docs/billing), [модели](https://ai.google.dev/gemini-api/docs/models).

## Как работает ИИ

- Описания во вкладке «Поток» — короткие заметки по метаданным, не анализ звучания или текста песни. Генерация не получает аудио. Если информации недостаточно, остаётся прежняя заглушка.
- Ранжирование включается только после 20 различных записей в серверной истории прослушиваний. До этого «Мой вайб» остаётся случайным, как согласовано ранее.
- Backend получает собственную историю пользователя из БД и до 60 кандидатов текущего каталога. Gemini возвращает только порядок индексов существующих кандидатов. Выдуманные ID и некорректные индексы не принимаются.
- Сохраняются текущие фильтры каталога, разнообразие, история воспроизведения и шестичасовое обновление подборки. ИИ влияет на порядок подходящих треков, а не сам создаёт каталог SoundCloud. «Мой вайб» учитывает также прежний вес недавних артистов/жанров.
- Клиент пробует обновить AI-рейтинг не чаще раза в 30 минут; серверный рейтинг кэшируется 6 часов для конкретного набора метаданных/истории. Описания кэшируются до 30 дней с учётом модели и языка. Результаты сохраняются в PostgreSQL.
- В Google передаются названия/исполнители/жанры/теги кандидатов и музыкальные признаки недавних прослушиваний. Telegram ID, username, аватар и API-ключи в промпт не включаются. Использование внешнего ИИ и данных предпочтений надо отразить в документах сервиса.
- Воспроизведение не ждёт Gemini. При отсутствии ключа, отказе, таймауте или квоте сохраняются обычные рекомендации; после ошибок есть пауза повторных обращений.

## Что проверено

Локально с SQLite, тестовыми Telegram/Google API и моделируемым кодеком: права на задания, дедупликация, последовательная очередь, Telegram file_id, зелёная кнопка-подсказка, неопределённая доставка без автодублирования, параметры FFmpeg для ID3/attached cover и контроль длительности; Gemini без ключа, кэш, бюджет, порог 20, выдача только существующих индексов, отсутствие идентификаторов аккаунта в промпте. HTTP-проверки авторизации и изоляции пользователей прошли. В Chromium проверены реальные обработчики обеих кнопок выгрузки, отправка выбранного URN, окно успеха и отсутствие ложного успеха при ошибке.

**Живая обработка аудио FFmpeg, отправка SoundCloud → Telegram, Google API и отображение обложки на телефонах из этой среды не проверены**: локального FFmpeg и ваших секретов здесь нет. После деплоя сначала выгрузите один короткий трек с обложкой и проверьте его в чате и на экране блокировки, затем проверьте описания и /health. Наличие кода и фикстур не выдаётся за успешную проверку живой интеграции.
