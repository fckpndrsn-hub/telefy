# Сводка и управление Mini App

## Установка

Все файлы из корня архива Telefy-Admin-Control.zip загрузите в корень существующего GitHub-репозитория с заменой. Dockerfile и telefy.html обязательны. Ничего из старого репозитория и папок web/assets не удаляйте. Существующие BOT_TOKEN, DATABASE_URL и TELEFY_ADMIN_IDS сохраняются. Таблицы в PostgreSQL создаются автоматически.

После Live в Render проверьте /health: `operations_build: telefy-operations-v1`. Отправьте боту `/admin`: появятся «Сводка пользователей» и «Управление Mini App». Прямые команды — `/stats` и `/app_admin`.

## Сводка

- Профили в БД — уникальные Telegram ID во всей общей базе Telefy (включая профиль, созданный по обращению к боту).
- Новые профили за 24 часа — по времени создания записи; не число покупок, прослушиваний или сессий.
- Пользователи бота — уникальные известные личные контакты. Повторный /start не увеличивает число. Старые подтверждённые контакты из таблицы напоминаний подгружаются при установке.
- Активны в боте за 24 часа — писали в личный чат или нажимали inline-кнопки. Этот учёт начинается с установки обновления; давняя активность задним числом не выдумывается.
- Заблокировали бота — известные события блокировки. Исторически не полученные события не восстанавливаются угадыванием.
- Открывали приложение за 24 часа / 7 дней — по существующему серверному учёту активности Mini App. В него также входит фоновое воспроизведение. Это разные пользователи, а не просмотры.
- Доступны для сообщений — личные контакты с разрешёнными сообщениями и без известного запрета доставки, до свежей проверки подписки на канал.
- Отключили сообщения — явный отказ в настройках, кнопкой или /stop.

Это собственная сводка Telefy, не полный список подписчиков @telefy_news и не статистика всех посетителей Telegram. Метрики доступны только администраторам в личном чате бота; публичный /api/app/status показывает лишь режим техработ и номер обновления.

## Перезагрузка Mini App

`/admin` → «Управление Mini App» → «Перезагрузить Mini App» → прочтите предупреждение → «Подтвердить».

Открытые страницы с установленным обновлением проверяют состояние каждые 15 секунд, а также при возвращении на экран. При изменении версии останавливается музыка, блокируются новые нажатия, завершается сохранение текущей библиотеки и страница обновляется один раз. Если сохранение библиотеки не удалось, обычная перезагрузка откладывается до следующей проверки. Лайки, плейлисты, сессии и настройки из БД не удаляются; localStorage не очищается.

Это обновление клиентских страниц. Оно не перезапускает процесс/контейнер Render и не устанавливает новый код из GitHub. Изменённые файлы сначала нужно развернуть обычным деплоем. Старые страницы без app-control.js дистанционно обновить этим механизмом невозможно — после первой установки нужно вручную переоткрыть Mini App.

Обычно команда доходит за 15–20 секунд; при остановленных фоновых таймерах телефона — после возвращения в приложение. Браузерные ограничения фонового выполнения не обходятся.

## Технические работы

`/admin` → «Управление Mini App» → «Выключить на техработы» → «Подтвердить».

Новые открытия показывают страницу «Telefy на технических работах». Уже открытое приложение при ближайшей проверке останавливает музыку и переходит на неё. Основные API приложения, включая новые музыкальные запросы, отвечают 503. Уже выданная внешняя ссылка на аудио не отзывается у источника; остановку воспроизведения выполняет установленный клиентский скрипт.

Завершающие записи в свою библиотеку и историю остаются доступны с прежней авторизацией, чтобы не обрывать сохранение на полпути. Пользовательские данные не удаляются. В состоянии техработ приостановлена отправка новых напоминаний и постов из очереди; уже начатую отправку невозможно отозвать. /start у подписанного пользователя показывает предупреждение о работах. Админка бота, webhook, /health и статус приложения продолжают работать.

Для возврата: «Управление Mini App» → «Включить Telefy» → «Подтвердить». Страница техработ проверяет доступность раз в 15 секунд и возвращается в приложение после включения. Есть кнопка ручной проверки. Музыка сама не включается.

Режим и версия обновления сохраняются в PostgreSQL и переживают рестарт/деплой. Подтверждение привязано к администратору, действует 10 минут и используется один раз. Повторное нажатие не повторяет команду. Если сервер выключен самим Render или БД недоступна, кнопки бота не заменяют восстановление хостинга.

## Проверки

С тестовыми Telegram API и SQLite проверены агрегаты, повторные контакты, доступ администратора, одноразовое подтверждение, выключение страниц/API, доступность бота и /health во время работ, сохранение режима, возврат в работу и отметка блокировки. В Chromium проверены клиентское обновление по версии, ожидание сохранения библиотеки, отказ от перезагрузки при ошибке сохранения, отсутствие цикла обновлений и экран работ. Реальный Render, PostgreSQL и физические телефоны этим тестом не проверялись.

Предыдущие функции постов, текстов и кнопок сохранены; инструкция — ADMIN-SETUP.md.
