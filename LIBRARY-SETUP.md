# Лайки и плейлисты в PostgreSQL

Распакуйте архив. Загрузите все файлы из него **в корень существующего репозитория GitHub с заменой**, как прошлые обновления. В папки web/assets вручную перемещать ничего не нужно: Dockerfile сам копирует файлы. Существующие server.py, user_database.py, requirements.txt, schema.sql и папку web не удаляйте.

Дождитесь успешного Live в Render. Используются прежние DATABASE_URL и BOT_TOKEN. Новых секретов и ручного выполнения SQL нет. Таблица telefy_user_libraries создаётся автоматически при первом подключении библиотеки, включая обновление уже существующей БД.

Проверка: откройте /health, найдите `"library_build":"telefy-library-db-v1"`. Затем откройте Mini App через @TelefyApp_Bot. Добавьте трек в любимые, создайте плейлист при действующем Max, закройте и снова откройте приложение. Проверьте также второе устройство с тем же Telegram-аккаунтом.

Старые данные браузера: в «Мой Telefy» появится «Перенести музыку из этого браузера в профиль». Кнопка запрашивает подтверждение аккаунта. При ошибке старые данные сохраняются; после успешного переноса прежние ключи удаляются. Перенос плейлистов требует действующего Max. Новые лайки/плейлисты не сохраняются в localStorage. Кэш общедоступного каталога и настройки интерфейса остаются в браузере.

Библиотека принадлежит Telegram ID проверенной серверной сессии; переданный клиентом ID владельца не используется. Сохраняются названия, обложки и идентификаторы записей, без аудиофайлов и временных URL потоков. Порядок треков сохраняется. При одновременных изменениях со второго устройства устаревшее сохранение отклоняется: библиотека обновляется с сервера, действие нужно повторить. При сетевой ошибке изменения откатываются, успех не показывается. Данные не удаляются при окончании Max; плейлистами вновь можно пользоваться после активации доступа.

Архив включает совместимые файлы ранее подготовленного Telefy Max; платёжные ключи и настройки не добавляются и не меняются этим обновлением. Код не активирует Max бесплатно.

Локальная проверка: API и сохранность после перезапуска проверены на SQLite; интерфейс — в Chrome с подставными Telegram/API-ответами. Живая PostgreSQL на вашем Render и два физических устройства из этой среды не проверялись.
