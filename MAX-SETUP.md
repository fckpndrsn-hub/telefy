# Telefy Max: 99 ₽ за календарный месяц через СБП

Это готовая интеграция для подключения магазина ЮKassa. Реальный магазин, ключи и подтверждение коммерческой оплаты ещё не получены. Без настройки провайдера приём оплаты выключен: кнопка не включает бесплатную подписку.

## Установка

Замените в корне GitHub все девять файлов кода из архива, включая Dockerfile. MAX-SETUP.md — эта инструкция. Существующие BOT_TOKEN, DATABASE_URL, ключи SoundCloud и TELEFY_BRIDGE_TOKEN сохраняются.

Таблицы telefy_max_orders и telefy_max_handoffs создаёт сам billing-модуль в PostgreSQL, отдельно от старых миграций. Записи оплат связаны с проверенным Telegram ID; @username не используется как идентификатор покупателя. Лайки и пользовательские плейлисты эта интеграция в БД не переносит: они пока локальные.

## Подключение ЮKassa

1. Откройте https://yookassa.ru/platezhi-dlya-samozanyatyh и подключите магазин как самозанятый. Адрес подготовленной страницы: https://telefy-8com.onrender.com/max .
2. Получите тестовый shopId и секретный ключ. Ключ вводится только в Environment Render, не в GitHub и не в переписку.
3. Подключите СБП и настройте регистрацию/передачу чеков для НПД по условиям своего магазина. Код не выдаёт собственные фиктивные чеки «Мой налог». Эта часть должна быть настроена и проверена с провайдером перед приёмом реальных денег.
4. Подготовьте и опубликуйте условия продажи с данными продавца, сроком доступа, порядком возврата и контактом поддержки. Ссылка обязательна перед включением оплаты.
5. Добавьте переменные ниже и выполните тестовую оплату. Не используйте тестовый магазин как рабочую платную подписку: тестовые подтверждения дают тестовый доступ.

| Переменная | Значение |
| --- | --- |
| YOOKASSA_SHOP_ID | ID магазина ЮKassa |
| YOOKASSA_SECRET_KEY | Секретный ключ этого магазина |
| YOOKASSA_TEST_MODE | `true` для тестового магазина; `false` только для рабочего |
| TELEFY_PUBLIC_URL | `https://telefy-8com.onrender.com` без завершающего `/` |
| TELEFY_MAX_TERMS_URL | HTTPS-ссылка на опубликованные условия Telefy Max |

В настройках HTTP-уведомлений ЮKassa укажите:

`https://telefy-8com.onrender.com/api/billing/webhook`

События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.

Для рабочего запуска нужны рабочие shopId/ключ и YOOKASSA_TEST_MODE=false. Не меняйте цены/статусы оплат напрямую в БД для имитации подтверждения.

## Как работает

Кнопка покупки открывает отдельную веб-страницу. Пользователь переносится туда по одноразовой ссылке на десять минут; ссылка погашается, затем удаляется из адресной строки. Страница имеет свою HttpOnly-сессию, поэтому покупка сохраняет привязку к Telegram ID и не требует ввода @username.

Создание платежа: только серверные 99.00 RUB, тип sbp, capture=true, save_payment_method=false. Автосписаний нет. Один ключ попытки создаёт один платёж, повторный клик не создаёт новую сумму к оплате. Браузерный return_url не активирует Max. Уведомление проверяется запросом к API ЮKassa; проверяются ID, сумма, валюта, владелец, признак тестового режима, способ оплаты и paid=true/status=succeeded.

Доступ начинается при первом подтверждении успешной оплаты. Месяц считается календарным по московскому времени: 31 января → последний день февраля; ранняя новая оплата добавляет месяц к текущей дате окончания. Повторные уведомления не добавляют срок. На границе expires_at доступ автоматически становится неактивным: cron не требуется. Интерфейс также проверяет срок и закрывает платные окна. Локальная переменная/кнопка покупки не выдаёт статус Max.

Полный возврат 99 ₽ после проверки API снимает соответствующий месяц; прочие подтверждённые оплаты учитываются отдельно. Частичные возвраты требуют отдельного рассмотрения, автоматическая частичная отмена срока не реализована.

## Проверка

До оплаты /api/max/status возвращает active=false. После успешной проверки платежа — active=true, expires_at, recurring=false. Возврат из банка сам по себе недостаточен. Закройте страницу до завершения: уведомление всё равно должно включить доступ. Повторите доставку уведомления: expires_at не должен измениться. Проверьте отмену и полный возврат. Перезапуск Render не должен терять статус. После конца срока активный доступ должен исчезнуть.

Локально проверены календарные даты, раннее ручное продление, дубликаты, поддельные уведомления, неверная сумма/валюта/владелец/способ оплаты, изоляция аккаунтов, возврат, одноразовая передача сессии и автоматическое выключение UI. Провайдер имитировался, БД проверялась через SQLite-адаптер. Рабочая PostgreSQL и реальная тестовая/боeвая оплата ЮKassa ещё не проверены.

Telegram требует Stars при продаже цифровых услуг внутри Telegram. Внешняя страница сама по себе не отменяет требования платформы; способ продажи и перехода к оплате необходимо учитывать перед выпуском. Этот код не заявляет исключения из правил Telegram.
