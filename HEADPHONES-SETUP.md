# Наушники и системное управление Telefy

Загрузите файлы из корня архива в корень существующего репозитория с заменой. Старые файлы и web/ не удаляйте. Внутри папок приложения ничего вручную менять не требуется: Dockerfile копирует audio-player.js в web/assets при сборке. Дождитесь Live в Render, полностью закройте Mini App и откройте заново. HTML содержит новую версию адреса audio-player.js для обновления кэша.

Архив включает предыдущее обновление бота с напоминаниями, чтобы HTML и сервер оставались совместимыми. Если оно уже установлено, его настройки сохраняются. Инструкция по напоминаниям — REMINDERS-SETUP.md; настройка планировщика не требуется для работы наушников.

Исправления:
- Системные команды play, pause, nexttrack и previoustrack через Media Session. Следующий и предыдущий треки используют существующую очередь и историю приложения.
- Пауза самого аудио, включая команду наушников и системное прерывание, обновляет кнопки на главном экране, в мини-плеере и большом плеере. При возвращении из фона состояние сверяется повторно.
- Продолжение с сохранённой позиции без повторного запроса потока при обычной паузе. Повторные команды Play/Pause не работают как переключатель в обратную сторону.
- Системные название, исполнитель, обложка и позиция обновляются. Системная перемотка поддержана через seekto.
- Внутренняя пауза при замене источника не отменяет запуск нового трека.
- Отсутствие Media Session или отдельных поддерживаемых команд не ломает основной плеер.

Проверено локально на моделируемых событиях аудио/Media Session: пауза/продолжение, команды Next/Previous, отсутствие лишнего запроса при продолжении, сохранение позиции, перемотка, смена источника, метаданные, выход из фона, отключение адаптера. Прежние проверки плавного прогресса и перемотки прошли.

Физические AirPods и Telegram на iPhone из этой среды не проверены. Приложение получает системную команду, а не само касание наушника. Если iOS/Telegram не передаёт nexttrack или жест AirPods назначен на другое действие, код страницы не может переназначить этот жест. После установки проверьте Play/Pause, двойное нажатие Next и возврат Previous на вашем устройстве.

Техническая основа: [спецификация Media Session](https://www.w3.org/TR/mediasession/).

## Системный плеер и Dynamic Island

Обновление также повторно регистрирует системные команды при возврате в приложение, обновляет длительность/скорость воспроизведения и освобождает команды перемотки ±10 секунд в пользу перехода между треками. Позиция доступна через системную шкалу, где её поддерживает оболочка.

Для встроенных браузеров, использующих название страницы вместо MediaMetadata, заголовок страницы также обновляется до «Трек — Исполнитель — Telefy». Это запасной путь для названия, он не гарантирует обложку или кнопки Next/Previous, если WebView не поддерживает Media Session.

После деплоя /health должен содержать `"player_build":"telefy-system-player-v2"`. Эта строка подтверждает серверную версию обновления, но сама по себе не подтверждает поддержку Media Session на телефоне.

После установки включите музыку вручную и проверьте:

1. На Android откройте шторку, на iPhone — Пункт управления и экран блокировки. Проверьте название, обложку, Play/Pause и смену трека.
2. На iPhone с Dynamic Island сверните Telegram и проверьте, появилась ли системная музыкальная активность. При её наличии удерживайте островок для разворачивания управления.
3. После системной паузы вернитесь в Telefy: все три кнопки должны показывать Play, а продолжение — идти с сохранённого места.

Появление в Dynamic Island определяется iOS и встроенным браузером Telegram. Эта сборка передаёт системные музыкальные метаданные и команды; успешное отображение островка на физическом устройстве пока не подтверждено. Отдельного web-API, заставляющего Mini App создать собственную Live Activity, здесь нет. Для собственного оформления такой активности потребуются отдельное iOS-приложение и Widget Extension с ActivityKit: [документация Apple](https://developer.apple.com/documentation/activitykit).

На Android системный плеер и дополнительные компактные панели зависят от Telegram и оболочки устройства. Собственная нативная MediaStyle-панель требует кода Android-приложения: [Android Developers](https://developer.android.com/reference/android/app/Notification.MediaStyle). Архив не устанавливает отдельное приложение и не добавляет наложение поверх других приложений.

Дополнительно пройден тест с настоящим audio-элементом и штатным MediaSession в Chromium: метаданные/обложка, системное состояние, три кнопки интерфейса при внешней паузе, сохранение позиции без повторного запроса потока и смена источника. Сам поток в этом тесте — локальный WAV; SoundCloud, AirPods, Telegram и телефон не эмулировались как реальные устройства.
