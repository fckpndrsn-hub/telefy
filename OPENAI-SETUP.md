# Telefy: OpenAI вместо Gemini

## Установка

Все файлы из корня архива Telefy-OpenAI.zip загрузите в корень существующего GitHub-репозитория с заменой. Старые файлы и web/ не удаляйте. Dockerfile обязателен: он добавляет openai_music.py и сохраняет исправленный порядок копирования клиентских скриптов после web/. В сборку включены текущая выгрузка с подписью Telefy, админка и режим техработ.

После успешного Live полностью закройте и заново откройте Mini App. На /health должно быть `music_features_build: telefy-export-openai-v1`, а объект `ai` должен содержать `provider: openai`. Объект gemini новой сборкой не используется. Наличие правильного номера сборки ещё не подтверждает валидность API-ключа.

## API-ключ

1. Откройте [OpenAI Platform → API keys](https://platform.openai.com/api-keys), выберите проект и создайте секретный API-ключ. Не присылайте его в чат и не загружайте в GitHub.
2. Проверьте доступный баланс/кредиты и биллинг **API-проекта**. Доступ к ChatGPT сам по себе не означает, что API-подключение настроено. Этот код не подключает платёжную карту и не меняет биллинг.
3. Render → telefy → Environment → Edit → Add Environment Variable:
   - KEY `OPENAI_API_KEY`, VALUE — новый секретный ключ;
   - KEY `OPENAI_MODEL`, VALUE `gpt-5.6-terra` (или другой доступный вашему проекту Responses-модельный ID с поддержкой Structured Outputs);
   - KEY `TELEFY_AI_DAILY_LIMIT`, VALUE `100` — общий предел новых внешних AI-запросов в сутки UTC;
   - если ранее стояло `TELEFY_AI_ENABLED=false`, замените на `true` для включения.
4. Save, rebuild and deploy. Дождитесь Live, переоткройте Mini App и откройте вкладку «Поток».

Существующие BOT_TOKEN, DATABASE_URL, TELEFY_ADMIN_IDS и SoundCloud-ключи сохраняются. GEMINI_API_KEY/GEMINI_MODEL больше не участвуют в работе. Автоматического переключения обратно на Google нет. Удалять старые переменные необязательно.

Модель по умолчанию gpt-5.6-terra, reasoning none, до 1024 выходных токенов. Для неподдерживаемой модели будет диагностируемая ошибка, а не незаметная замена другим платным провайдером. Лимит числа запросов не является долларовым лимитом. Расходы и доступные ограничения отдельно контролируются в API-проекте OpenAI. [Модель](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [первое подключение API](https://developers.openai.com/api/docs/quickstart).

## Диагностика

Объект `ai` в /health не показывает ключ, историю музыки или полный текст ошибки:

- `configured:false` / `not_configured` — нет OPENAI_API_KEY или адаптер отключён.
- `idle` — ещё не было успешного внешнего запроса, например вкладку «Поток» ещё не открывали.
- `ready` — обработан успешный ответ OpenAI.
- `invalid_api_key` — ключ не принят, HTTP 401.
- `billing_required` — API вернул insufficient_quota; проверить баланс/кредиты и ограничения проекта.
- `rate_limited` — ограничение запросов/токенов.
- `project_or_region_denied` — отказ в доступе проекту/региону, HTTP 403.
- `model_unavailable` — модель не найдена или недоступна проекту.
- `invalid_request` — API отклонил параметры/схему. Указываются только безопасные http_status/error_code.
- `daily_limit` — исчерпан лимит TELEFY_AI_DAILY_LIMIT.
- `incomplete_response`, `refused`, `unavailable` — неполный ответ, отказ модели или сетевой/форматный сбой.

После HTTP-ошибок есть пауза повторных попыток. Кэшированные результаты продолжают работать. Перезапуск процесса сбрасывает кратковременное состояние диагностики, но не кэш и не суточный счётчик в БД. У OpenAI отдельный счётчик, чтобы старые попытки Gemini не заблокировали миграцию.

## Поведение

Описание запрашивается автоматически во вкладке «Поток». Используются название, исполнитель, жанр и теги; аудио в OpenAI не отправляется. Модель не должна придумывать биографию, даты релизов, статистику, цитировать тексты песен или утверждать, что прослушала запись. Если полезного описания нет, карточка показывает «Описание пока недоступно». Ожидание ограничено, старый ответ не заменяет описание другого трека.

Рекомендации используют собственную серверную историю последних 20 различных прослушанных записей. До этого сохраняется случайный «Мой вайб». Модель ранжирует только переданных кандидатов, не добавляет выдуманных треков и не обходит фильтры каталога. Пользовательские ID, username и аватары в промпт не передаются; передаются музыкальные метаданные и признаки предпочтений. Этот внешний процесс следует отражать в документах сервиса.

Описания кэшируются до 30 дней, рейтинг — до 6 часов для соответствующего набора истории и кандидатов. Разные модели/провайдеры имеют разные ключи кэша. Запросы отправляются только с backend на фиксированный адрес api.openai.com; ключ не включается в URL, HTML или frontend. Используется `store:false`, что отключает сохранение Response как объекта, но само по себе не является обещанием Zero Data Retention со стороны провайдера.

Подпись аудиовы​​грузки включает жирную ссылку «Трек выгружен с помощью Telefy» и parse_mode HTML в обеих ветках отправки: нового файла и Telegram file_id. Уже отправленные сообщения не редактируются автоматически. После установки запросите новую выгрузку, чтобы увидеть новую подпись.

## Проверено

Локально с SQLite и фикстурами: Responses JSON/schema, Bearer-ключ только в заголовке, store=false, успешный ответ, кэш, суточный лимит, безопасная диагностика insufficient_quota, сохранение кэша при ошибке, порог 20 треков и отсутствие идентификаторов аккаунта в промпте. Выгрузка проверена на параметры нового multipart-сообщения и отправки Telegram file_id, жирную ссылку, HTML-режим и зелёную кнопку-подсказку. Повторно проверены HTTP-авторизация, очереди, карточка потока и приоритет Docker COPY.

Живой вызов OpenAI и отображение результата на вашем телефоне требуют проверки после добавления собственного ключа и деплоя. Реальных платных запросов во время разработки не выполнялось.
