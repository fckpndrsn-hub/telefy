# Напоминания Telefy и свои медиа

## 1. Обновить существующий сервис

Распакуйте Telefy-Bot-Reminders.zip. Файлы из корня архива загрузите с заменой в корень существующего репозитория telefy. Ничего из репозитория не удаляйте: это дополнение к текущей сборке. В частности, server.py и папка web остаются на месте. Вручную раскладывать JS в web/assets не нужно — Dockerfile делает это при сборке.

Дождитесь Live в Render. Существующие BOT_TOKEN, DATABASE_URL и ключи SoundCloud остаются. Схема PostgreSQL создаётся автоматически. По /health должно появиться `"reminders_build":"telefy-reminders-v1"`.

## 2. Дать себе доступ к загрузке медиа

1. В личном чате с @TelefyApp_Bot отправьте `/id`.
2. Render → ваш сервис telefy → Environment → Edit → Add Environment Variable.
3. KEY: `TELEFY_ADMIN_IDS`. VALUE: **ваш числовой Telegram ID**, который ответил бот. Это не @username, не ID канала и не токен. Несколько администраторов — ID через запятую.
4. Save, rebuild and deploy. Дождитесь Live.
5. Отправьте боту `/reminders_admin`. Выберите «48 часов», «3 дня», «7 дней», «14 дней» или «1 месяц».
6. Отправьте фото, видео, GIF, аудио или документ обычным вложением в этот же личный чат в течение 10 минут. На каждом этапе хранится одно медиа. Новая загрузка заменяет предыдущее.
7. Нажмите «Посмотреть сообщение» / «Предпросмотр» — пример придёт только вам. «Убрать медиа» возвращает текстовое сообщение.

Без TELEFY_ADMIN_IDS никто не получает права на загрузку. Администратор может загрузить разные медиа для всех пяти этапов. Хранятся Telegram file_id в PostgreSQL; файлы на диск Render не скачиваются. Предпросмотр не меняет сроки напоминаний пользователей. Кнопка «Не напоминать» в предпросмотре отключит напоминания лично вам.

## 3. Планировщик для бесплатного Render

На постоянно работающем сервисе отправка проверяется в фоновом потоке каждые 30 секунд. Бесплатный Render засыпает без входящих запросов, поэтому для него предусмотрен отдельный запуск проверки через GitHub Actions. Второй сервер не нужен.

1. В GitHub откройте репозиторий telefy → Settings → Secrets and variables → Actions → New repository secret.
2. Name: `BOT_TOKEN`. Secret: существующий токен **этого же** бота, как в Render. Add secret. В файлы репозитория его не вставляйте.
3. На странице Code нажмите Add file → Create new file. В имени укажите **полный путь** `.github/workflows/telefy-reminders.yml`. Скопируйте содержимое одноимённого файла из папки `.github/workflows` архива. Commit changes в основную ветку main. Если загрузка папки сохраняет структуру, можно загрузить её целиком; файл не должен оказаться в корне.
4. GitHub → Actions → Telefy reminders → Run workflow → Run workflow. Дождитесь зелёного результата.
5. Затем расписание запускается каждые 5 минут. При отсутствии кандидатов результат `Processed reminder candidates: 0` — нормален. Проверка не отправляет тестовую рассылку всем пользователям и не сдвигает сроки.

По умолчанию workflow обращается к https://telefy-8com.onrender.com. Если адрес изменился: Settings → Secrets and variables → Actions → Variables → New repository variable, имя `TELEFY_PUBLIC_URL`, значение HTTPS-корень вашего сервиса без завершающего пути. Сам BOT_TOKEN по HTTP не передаётся — workflow вычисляет подпись для служебного маршрута. Служебный адрес без правильной подписи возвращает 403.

GitHub может задерживать запуски расписания; доставка не гарантируется в точную секунду. У неактивного публичного репозитория расписание может автоматически отключиться после 60 дней без активности: проверяйте Actions. Приостановка Render по квоте или недоступность PostgreSQL тоже задержат отправку. Локальные проверки не заменяют контроль первого реального запуска на вашем аккаунте.

Документация: [Render Free](https://render.com/docs/free), [расписание Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [секреты Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

## Поведение

- После последнего использования приложения: 48 часов → 3 дня → 7 дней → 14 дней → 1 календарный месяц. Январь 31 → февраль 28/29. После пятого этапа без новых посещений сообщений больше нет.
- Учитывается открытое видимое приложение и фактическое воспроизведение в фоне. Серверные служебные запросы и закрытая вкладка без воспроизведения таймер не сбрасывают. Обновление времени активности ограничено примерно двумя минутами.
- Возвращение в приложение сбрасывает всю цепочку. Повторный `/start` сам по себе не сдвигает уже существующую цепочку.
- Если сервер пропустил несколько сроков, отправляется только последнее актуальное сообщение, без пачки старых.
- Бот пишет только пользователям, у которых есть подтверждённый личный контакт с ботом. Старые контакты восстанавливаются по сохранённым кнопкам запуска; без такого следа пользователь должен нажать Start. Первоначальное включение не запускает массовые напоминания задним числом.
- Перед доставкой проверяется подписка на канал. Ушедшим из канала, отключившим напоминания и заблокировавшим бота не отправляется.
- Отключить: «Не напоминать» под сообщением, `/stop` в боте или переключатель «Напоминания в боте» в настройках приложения. Включить: `/remind` или переключатель.
- На ограничение Telegram 429 соблюдается retry_after. При неоднозначном сетевом обрыве или падении во время отправки текущий этап может быть пропущен, чтобы не дублировать уже доставленное сообщение. Это доставка по мере возможности, а не гарантия exactly-once.
- Глобальная пауза: Render Environment `TELEFY_REMINDERS_ENABLED=false`. Вернуть `true` для включения.

## Тексты

**48 часов:** Твоя музыка заждалась 🎧 Загляни в Telefy — выбери трек под настроение.

**3 дня:** Что сегодня на повторе? 🎵 Открой Telefy и найди свой следующий любимый трек.

**7 дней:** Давно не слушались 🎶 Твой вайб — в Telefy.

**14 дней:** Самое время сменить саундтрек ✨ Загляни в Telefy за музыкой под настроение.

**1 месяц:** Telefy на связи 🎧 Заходи, когда захочется музыки.

У каждого сообщения кнопки «Открыть Telefy» и «Не напоминать». Свои подписи медиа не заменяют эти тексты: назначенное вложение отправляется с соответствующим текстом этапа.

## Проверено локально

Тестовые Telegram API и SQLite: сроки и календарный месяц, возвращение, отсутствие пачки и повторов при конкуренции, отмена после возвращения, 429/обрыв/блокировка, доступ администратора, все пять типов вложений, предпросмотр/удаление. HTTP: собственный аккаунт, защита настроек и служебного запуска. Chromium: переключатель, сохранение/откат ошибки, неактивная вкладка, существующие пять кнопок бота и стартовые Тренды. На Render код этим архивом автоматически не установлен; реальную доставку Telegram проверяйте после деплоя.
