# Telefy: PostgreSQL + профиль Telegram

Профили и последние 20 квалифицированных прослушиваний сохраняются в PostgreSQL. Лайки и плейлисты пока хранятся в браузере. История вкуса не является системой биллинга или защищённым счётчиком прослушиваний.

## Установка в Render

1. Создай **New → Postgres** в том же регионе, где работает Telefy. Выбор тарифа остаётся за тобой; проверь стоимость и ограничения хранения перед созданием.
2. В базе открой **Connect / Internal Database URL**. В веб-сервисе **telefy → Environment → Edit** добавь:
   - `DATABASE_URL` = Internal Database URL целиком.
   - `BOT_TOKEN` = токен именно **@TelefyApp_Bot** из BotFather. Не Client Secret SoundCloud и не Bridge Token.
3. Сохрани текущие `SOUNDCLOUD_CLIENT_ID`, `SOUNDCLOUD_CLIENT_SECRET`, `TELEFY_BRIDGE_TOKEN` и все остальные переменные.
4. Распакуй архив и загрузи его файлы в **корень GitHub**, с заменой. Существующие `server.py`, `web/`, `audio-player.js` и файлы бота оставь на месте. Новый `profile_server.py` подключает существующий сервер; его музыкальные и бот-маршруты сохраняются.
5. Дождись **Live**. Открой приложение через Telegram, не обычную браузерную ссылку. На первом входе таблицы создаются автоматически. При следующем открытии профиль обновляется.

Проверка правильного деплоя: открой `/health`. Должно быть `build: "telefy-profile-db-v1"`, `database_configured: true`, `telegram_configured: true`. Это проверяет версию и наличие переменных, а не соединение PostgreSQL: реальное подключение проверяется при входе. Если build отсутствует, запускается старая сборка. Конечная строка Dockerfile должна быть `CMD ["python", "profile_server.py"]`.

Если текущий server.py использует проверку обязательной подписки через модуль telefy_bot, она продолжает действовать. Бот должен иметь права администратора @telefy_news.

## Что хранится

`telefy_users`: Telegram ID (BIGINT), username (необязательный и изменяемый), имя, фамилия, URL фото, язык, признак Telegram Premium, время создания/обновления/последнего входа.

`telefy_user_sessions`: SHA-256 хеш случайного токена, Telegram ID, срок действия 7 дней. Сам токен хранится только в HttpOnly/Secure/SameSite cookie. Telegram Premium не даёт подписку Telefy Max.

`schema.sql` — идемпотентное создание таблиц и индексов без удаления существующих данных. Пароли, токены Telegram и SoundCloud в пользовательскую таблицу не записываются.

## API

- `POST /api/auth/telegram`: `{ "initData": "...Telegram.WebApp.initData..." }`. Проверка подписи BOT_TOKEN и свежести данных (1 час), upsert профиля, создание cookie.
- `GET /api/me`: только текущий пользователь по cookie, без поиска чужих профилей по @username/ID.
- `POST /api/auth/logout`: удаление текущей сессии.

Оба POST требуют same-origin запросы. Аватарка выводится через подписанный `photo_url`; если Telegram не отдаёт фото или ссылка перестала работать, показывается первая буква имени. Отдельный Bot API getFile не вызывается, поэтому секрет бота не может попасть в URL фотографии.

## Локальная проверка

SQLite разрешён только явной переменной `TELEFY_DEV_SQLITE_PATH` при отсутствии Render. На Render обязательно DATABASE_URL: незаметного сохранения пользователей в исчезающий файл /tmp нет. Проверки в рабочей папке: work/test_user_database.py и work/test_profile_http.py.

Реальный вход Telegram и подключение PostgreSQL нужно проверить после развёртывания: в локальных тестах подписи и БД проверяются с тестовым токеном и временным SQLite.

## Музыкальное обновление

Первый вход показывает случайный подходящий трек без автозапуска. «Мой вайб» учитывает последние 20 воспроизведений продолжительностью от 30 секунд. Таблица telefy_taste_events создаётся автоматически; доступ к истории — только по сессии своего профиля через GET/POST /api/me/taste.

«Рекомендуем послушать» использует шестичасовые снимки. Именные редакционные артисты могут выходить за диапазон 5–10 тысяч подписчиков. Все записи проходят общие жанровые/языковые фильтры; Cupsize не имеет обхода правил. Большие подборки заполняются до 250 подходящих доступных записей, фактическое число зависит от метаданных и наличия в SoundCloud.

При пустой выдаче после открытия главного экрана доступна агрегированная диагностика: /api/soundcloud/search?q=telefy%3Afreshmen%3Adiagnostics — только в авторизованной сессии. Ответ содержит счётчики этапов и коды ошибок, без секретов.


## Обновление 16 ноября: режимы и Мой вайб

До 20 различных треков с 30 секундами фактического воспроизведения «Мой вайб» выбирает случайную подходящую музыку. Повтор одного трека не приближает порог. С 20 различных треков учитывается недавний вкус и добавляются непрослушанные похожие записи. При Max создаётся один обновляемый плейлист «Мой вайб #1» на 20 записей. Это автоматическое обновление локального плейлиста; лайки и сами плейлисты всё ещё не синхронизируются с PostgreSQL.

Обложка каждой подборки закрепляется в браузере и не меняется при обновлении треков. Чилл отбирается по мягким жанрам/тегам с исключением агрессивных записей; для R&B учитываются исполнители рэп-сцены. Тренды используют свежие загрузки и доступные показатели популярности SoundCloud, это не чарт Spotify и не аудиоанализ. Диагностика в своей авторизованной сессии: /api/soundcloud/search?q=telefy%3Adiscovery%3Adiagnostics. Ошибка источника отличается от отсутствия подходящих записей.

Для установки замените все файлы архива в корне репозитория и дождитесь деплоя. Переменные окружения прежние. /health содержит music_build: telefy-request-budget-v3-20261116. Если значение другое — запущена предыдущая версия. Схема БД обновляется автоматически. Локальные проверки используют фикстуры API/Telegram и SQLite; живую выдачу SoundCloud и физические телефоны необходимо проверить после развёртывания.


## Исправление нагрузки и HTTP 429

Удалены стартовый семистраничный обход сцены и автоперебор всех страниц коллекции. Открытие подборки загружает одну порцию; дальнейшие порции — по кнопке «Загрузить ещё». Повторное открытие использует уже полученный треклист. Рекомендации запрашивают одну ограниченную порцию, сохраняя предыдущую при сбое. Поиск артистов с лимитами до 50 записей использует общий серверный кэш; одинаковые параллельные запросы объединяются. Метаданные ограничены двумя одновременными обращениями с интервалом не менее 1,3 секунды между стартами; очередь ограничена.

Retry-After и X-Ratelimit-Reset задают общую паузу после 429. Потоки с исчерпанной долгой квотой учитываются отдельно от метаданных. Сохранённые результаты не очищаются при недоступности источника. Кэш сервера хранится в памяти процесса и сбрасывается при перезапуске; обложки и ранее показанные рекомендации также сохраняются браузером. Ошибки источника не кэшируются как успешные пустые подборки. Для хитов без даты релиза допустима дата загрузки при отборе диапазона 2017–2026, без подстановки выдуманной даты релиза в данные трека.

Новая версия /health: music_build=telefy-request-budget-v3-20261116. Там же soundcloud_limits, soundcloud_last_rate_limit и soundcloud_retry_after. В логах Render HTTP 429 содержит группу oauth/metadata/stream, остаток и время сброса, без токенов. Расширенная диагностика только в авторизованной сессии: /api/soundcloud/search?q=telefy%3Arequests%3Adiagnostics. Эти диагностические адреса сами не обращаются к SoundCloud. Если квота уже исчерпана, обновление не отменяет существующий лимит провайдера: нужно дождаться указанного resetAt.
