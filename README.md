# Проверка SoundCloud через Render

Этот пакет не содержит ключей. Он не принимает, не проксирует и не хранит музыку.
Только поиск, OAuth-токены и получение подписанного адреса HLS.
Доступность SoundCloud с Render ещё нужно подтвердить после развёртывания.

1. Создай аккаунты Render и GitHub, если их нет.
2. Создай приватный репозиторий и загрузи в корень только файлы этой папки.
   Папку `.telefy-private` и локальные JSON с ключами загружать нельзя.
3. В Render выбери New → Blueprint, подключи репозиторий. render.yaml задаёт
   бесплатный Docker Web Service в регионе Frankfurt. Проверь план Free до запуска.
4. Введи SOUNDCLOUD_CLIENT_ID и SOUNDCLOUD_CLIENT_SECRET в секретные переменные.
   TELEFY_BRIDGE_TOKEN генерируется автоматически. Сохрани его локально для связи.
5. После Deploy открой https://ИМЯ.onrender.com/health. Ответ {"ok":true}
   проверяет только запуск сервера, не доступ к SoundCloud.
6. Перезапусти локальный сервер Telefy: заверши старый процесс serve.py и запусти
   START.cmd. Открой http://127.0.0.1:8915/bridge-setup.html.
7. Введи URL Render и TELEFY_BRIDGE_TOKEN. Форма проверит настоящий поиск SoundCloud;
   только после успешного поиска подключение сохранится. Затем обнови Telefy.

Если API работает, но воспроизведение нет, отдельно проверяем доступ браузера
к CDN SoundCloud и HLS. Сервер не меняет доступность CDN на устройстве слушателя.

Free-сервис засыпает после 15 минут простоя. Первое обращение может быть долгим;
это вариант для теста, не окончательный тариф для музыкального продукта.
Токены на бесплатном диске не переживают пересоздание сервиса; не делай частые
перезапуски, чтобы не расходовать лимит выдачи токенов SoundCloud.
Входящие API-запросы защищены отдельным секретом, ограничены 90 запросами в минуту.

Документация: https://render.com/docs/free и https://render.com/docs/regions
